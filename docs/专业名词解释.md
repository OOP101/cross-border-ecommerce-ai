# 专业名词解释

> 口语化解释 + 每个名词在项目里的具体位置，供学习与面试口语表达使用。按「大模型基础 / RAG 检索 / 工程架构 / 安全 / 质量评估」分组。

---

## 一、大模型基础

**LLM（大语言模型）**
通过海量文本训练出来的 AI，能理解和生成自然语言。本项目里它扮演三个角色：客服回答、写营销文案、做翻译。

**Prompt（提示词）**
发给大模型的指令文本。写得好坏直接决定输出质量。项目里每类任务都有固定模板（如 `services/chat.py` 的 SYSTEM_PROMPT 规定客服要"可溯源、不编造"）。

**System Prompt（系统提示词）**
对话开始前给模型设定的"人设与规矩"，优先级高于用户输入。项目里客服的系统提示词要求：基于知识库回答、没有相关信息要如实说并建议转人工。

**Token**
大模型计费和计量的最小文本单位，约等于半个到一个汉字。项目的 Token 用量取自 LLM 返回的真实 usage（`core/llm/base.py::extract_usage`），驱动数据洞察看板的成本统计。

**幻觉（Hallucination）**
模型一本正经地编造事实。商业客服不能容忍，所以项目用 RAG + 溯源 + 转人工三层机制兜底。

**API Key（密钥）**
调用大模型服务的"通行证"，形如 `sk-xxxx`。放在 `backend/.env` 里，被 git 忽略不会进仓库。

**OpenAI 兼容协议（openai_compatible）**
不是指 OpenAI 公司，而是它定义的接口格式（`POST /chat/completions` + messages 数组）成了行业通用标准。DeepSeek、小米 MiMo、通义千问、硅基流动都兼容——所以项目一套实现代码能接所有厂商（`core/llm/openai_compatible.py`），换厂商只改 `.env` 三行。

**硅基流动（SiliconFlow）**
一个国产大模型聚合平台，一个 Key 可以调用 DeepSeek、Qwen、GLM、Kimi 等多家模型。地址 `https://api.siliconflow.cn/v1`，适合对比选型。

## 二、RAG 与检索

**RAG（检索增强生成）**
先从知识库检索相关资料，塞进提示词再让模型生成——回答"有据可依"而不是靠模型记忆瞎猜。项目问答链路：提问 → 意图识别 → 检索 → 拼接上下文 → 生成 → 附来源返回。

**Embedding（向量化）**
把一段文字变成一串数字（向量），语义相近的文字向量距离也近。是"按意思搜索"的基础。项目接口在 `core/embeddings`（当前为 Mock，可切真实模型）。

**向量数据库**
专门存向量并支持"找最相似"的数据库。项目内置内存版（JSON 持久化）和 Chroma 两种实现，接口在 `core/vector_store`。

**语义分块（Chunking）**
把长文档切成小块再入库——块太大检索不精准，太小丢上下文。项目按段落/句子边界切，500 字一块、相邻块重叠 128 字（`utils/chunking.py`）。

**BM25**
经典的关键词检索算法，按"查询词在文档里出现的频率和稀有程度"打分。擅长精确匹配缩写、型号（如 L/C、FOB），正好补向量检索的短板。项目用纯 Python 实现（`services/rag/bm25.py`），零依赖。

**RRF（倒数排名融合）**
把向量检索和 BM25 两路结果合并排序的方法：按名次给分（`权重/(60+名次)`）再相加。只用排名不用原始分数，巧妙避开了两套分数"单位不同没法直接加"的问题（`services/rag/retriever.py`）。

**重排序（Rerank）**
检索先"广撒网"保证不漏，再对候选精排保证最相关的排前面。项目默认启发式打分，预留了换成 bge-reranker 等交叉编码器模型的接口（`services/rag/rerank.py`）。

**混合检索（Hybrid Retrieval）**
向量检索（懂语义）+ BM25（懂关键词）双路召回 + RRF 融合。项目实测配置 52 条评测集后 Recall@3 = 100%。

**知识溯源**
每个回答附上"依据哪份文件的哪段话"。用户可以核对，管理方可以审计——商业场景必须项。

**Recall@K / MRR**
检索质量的两个指标。Recall@3 = 前 3 条结果里命中正确答案的比例；MRR = 正确答案排名的倒数的平均值（越接近 1 排得越靠前）。评测脚本：`scripts/eval_rag.py`。

## 三、工程与架构

**可插拔架构（工厂模式）**
外部依赖都藏在统一接口后面，换实现不改业务代码。项目四大可插拔点：LLM、Embedding、向量库、Agent，各有 `base.py`（接口）+ `factory.py`（按配置选择实现）。

**Mock 与降级**
Mock = 假实现（返回固定演示数据）。没配 API Key 时自动降级用 Mock，系统照样能跑——开发、测试、演示都不被外部服务卡脖子。

**故障转移（Failover）**
主服务挂了自动切到备用服务。项目的 `LLM_FAILOVER` 配置备用端点链，主端点连接失败/超时/限流/密钥失效时自动切换（当前：小米 MiMo 主 + DeepSeek 备）。流式回答在"还没吐出第一个字"前可以切，开始输出后就不切了——避免内容重复。

**SSE（Server-Sent Events，流式输出）**
服务器通过普通 HTTP 持续往浏览器推送文字片段，用户看到"打字机效果"，不用等整段生成完。比 WebSocket 轻量（单向推送够用）。项目 `/chat/stream` 接口 + 前端 ReadableStream 消费。

**异步并发（asyncio.gather）**
同时发起多个请求而不是排队等。项目文案"一键生成"要调 4 次 LLM，并发后总耗时 = 最慢那一次（而不是四次相加）。

**多租户（Multi-tenant）**
一套系统服务多家公司，彼此数据隔离。项目用 `tenant_id` 字段贯穿知识库、会话、看板，检索时只查本租户的知识，防止串数据。

**LRU 缓存**
"最近最少使用"淘汰策略的缓存：容量满了删最久没用的。项目翻译记忆第一级是进程内 LRU（上限 1 万条），第二级落 SQLite 数据库——快且重启不丢。

**Alembic（数据库迁移）**
给数据库表结构做"版本管理"的工具：改字段写成迁移脚本，各环境按序升级、可回滚。项目已有两个迁移（初始建表、加 tenant_id 列）。

**Docker / docker-compose**
把应用连同环境打包成容器，任何机器行为一致；compose 编排多个容器（前端 + 后端）。项目有开发版和生产版两套编排。

## 四、安全

**JWT（JSON Web Token）**
登录后服务端发的"电子工牌"（三段式：头.载荷.签名），之后每次请求出示即可证明身份，服务端不用存会话。项目用标准库手写 HS256 实现（`core/security.py`）。

**PBKDF2（密码哈希）**
存密码不是存原文，而是存"加盐慢哈希"后的值——就算数据库泄露也还原不出原密码。项目 10 万轮迭代 + 每用户独立随机盐。

**越权**
用户访问了不属于自己的权限。项目修过一个典型漏洞：注册接口曾信任客户端传的"角色"字段，任何人可传 `role=admin` 自助提权——修复后角色由服务端强制指定。

**CORS（跨域资源共享）**
浏览器的安全机制：A 网站的页面默认不能随便请求 B 网站的接口，B 要明确"允许 A"。注意 `*`（允许所有源）和"允许携带凭据"不能同时开——浏览器直接拒绝。

**PII 脱敏**
PII = personally identifiable information（个人身份信息：手机号、银行卡、身份证号）。入库前自动识别并打码，项目在 `utils/text_clean.py`。

## 五、术语与产品概念

**术语库（Terminology）**
行业术语的标准译法对照表（如 FOB=离岸价）。存数据库表，翻译时注入提示词强约束模型照用，保证合同级一致性。管理接口：`/api/v1/translation/terminology`。

**翻译记忆（Translation Memory）**
翻过的句子存下来，下次遇到原句直接复用——又快又保证前后一致。项目两级实现：进程内 LRU + SQLite 持久化（跨重启命中）。

**MOQ / FOB / CIF / L/C**
外贸高频缩写：MOQ 最小起订量；FOB 离岸价（卖方负责到装船）；CIF 到岸价（含运费保险）；L/C 信用证（银行担保付款）。项目示例知识库默认内置这些术语。

**意图识别（Intent Classification）**
判断用户这句话想干什么（查订单/售后/问产品/要翻译）。项目用关键词规则实现（`services/agent/workflow.py`），预留 LangGraph 升级为模型判断。

**转人工（Human Handoff）**
AI 搞不定或不该管的问题（投诉、退款、法律）自动转真人客服。项目按关键词规则触发，回答里明确告知用户。

**LangGraph**
LangChain 家的"多 Agent 流程编排"框架，把多个步骤画成图（分类 → 路由 → 执行）按图执行。项目预留了接口，是后续从规则路由升级的方向。

**MCP（Model Context Protocol）**
把工具能力（查库、检索、计算）封装成标准接口供大模型调用的协议。列入项目长期路线（L3）。
