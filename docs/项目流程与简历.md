# 跨境电商一站式智能服务平台 — 项目流程与简历指南

## 一、项目概述

**项目名称**：国际贸易上市公司一站式智能服务平台

**项目定位**：面向跨境电商企业的 AI 赋能平台，整合多语言文案写作、智能客服、知识库检索、数据洞察、亚马逊 SP-API 对接等核心能力，帮助卖家提升运营效率、降低人力成本。

**技术栈**：
- **后端**：FastAPI + SQLAlchemy + SQLite（可切换 PostgreSQL/MySQL）
- **前端**：Vue 3 + Vite + Element Plus
- **AI 层**：阿里云百炼（通义千问）+ OpenAI 兼容接口
- **向量库**：ChromaDB（生产）/ 内存向量（开发）
- **嵌入模型**：阿里云 text-embedding-v3
- **外部对接**：Amazon SP-API（python-amazon-sp-api + boto3）

### 2.2 模块详解

#### 模块一：AI 文案写作（/api/v1/copywriting）

**业务流程**：
1. 用户输入商品信息（名称、品类、卖点、目标市场、语言）
2. 系统构建结构化 Prompt，注入跨境电商领域知识
3. 调用 LLM 生成多类型文案：
   - 商品标题（SEO 优化）
   - 商品描述（本地化表达）
   - 广告语（吸引点击）
   - 营销文案（活动推广）
   - SEO 关键词（搜索排名）
4. 记录 API 用量，返回结构化结果

**技术亮点**：
- 支持 10+ 语言，本地化适配目标市场文化
- Prompt 工程优化，注入行业最佳实践
- 结构化输出解析，前端可直接渲染

---

#### 模块二：RAG 智能客服（/api/v1/chat）

**业务流程**：
1. 用户发送问题
2. 意图识别：判断问题类型（产品咨询/物流/售后/闲聊）
3. 知识库检索：
   - 向量相似度搜索（ChromaDB）
   - BM25 关键词匹配
   - 混合排序（Hybrid Search）
4. 构建带上下文的 Prompt
5. LLM 生成回答，附带引用来源
6. 判断是否需要人工介入（复杂问题转人工）
7. 记录对话历史，支持多轮会话

**技术亮点**：
- RAG（检索增强生成）架构，回答有据可查
- 混合检索策略，兼顾语义和关键词
- 意图识别 + 人工介入阈值，保证服务质量
- 会话状态管理，支持多轮对话

---

#### 模块三：知识库管理（/api/v1/knowledge）

**业务流程**：
1. 上传文档（PDF/Word/TXT/Markdown）
2. 文档解析：提取文本内容
3. 文本分块（Chunking）：
   - 按段落/句子切分
   - 设置重叠窗口（overlap）保留上下文
4. 向量化：调用嵌入模型生成向量
5. 存储到向量库（ChromaDB）
6. 支持搜索、删除、列表查看

**技术亮点**：
- 多格式文档支持
- 智能分块策略，保留语义完整性
- 向量持久化，重启不丢失

---

#### 模块四：多语言翻译（/api/v1/translation）

**业务流程**：
1. 输入源文本、源语言、目标语言
2. 查询翻译记忆（LRU 缓存 + SQLite 持久化）
3. 若命中缓存，直接返回（零延迟）
4. 若未命中：
   - 加载术语库（行业专业词汇标准译法）
   - 构建带术语约束的 Prompt
   - 调用 LLM 生成翻译
5. 存入翻译记忆，下次复用
6. 记录 API 用量

**技术亮点**：
- 两级缓存（内存 LRU + SQLite），高频翻译零延迟
- 术语库约束，保证专业词汇一致性
- 翻译记忆复用，降低成本

---

#### 模块五：数据洞察（/api/v1/analytics）

**业务流程**：
1. 聚合对话数据：总对话数、平均响应时间、用户满意度
2. 统计 API 用量：Token 消耗、调用频次
3. 提取高频问题：分析用户最关心的问题
4. 生成运营看板数据

**技术亮点**：
- 实时数据聚合
- 高频问题挖掘，辅助业务决策

---

#### 模块六：亚马逊 SP-API 对接（/api/v1/amazon）

**业务流程**：
1. **OAuth 授权**：
   - 生成授权 URL，引导卖家授权
   - 处理回调，获取 Refresh Token
   - 自动刷新 Access Token
2. **订单管理**：
   - 查询订单列表（按时间/状态筛选）
   - 获取订单详情、订单项
3. **商品目录**：
   - 搜索商品（按关键词/ASIN）
   - 获取商品详情
4. **库存管理**：
   - 查询 FBA 库存汇总
5. **报表**：
   - 创建报表请求
   - 查询报表状态
   - 下载报表文档

**AI 联动功能**：
- **订单智能分析**：拉取订单数据 → LLM 分析销售趋势、热销商品、客单价
- **热销商品文案写作**：从订单提取热销 ASIN → 自动生成多语言文案
- **客服订单上下文**：查询订单详情 → 注入客服对话上下文
- **商品描述翻译**：批量翻译订单中的商品描述

**技术亮点**：
- 支持 10 个站点（US/UK/DE/FR/IT/ES/JP/AU/IN/CA）
- AWS Signature V4 签名认证
- LWA OAuth 2.0 授权流程
- AI 与订单数据深度联动

## 三、技术架构亮点

### 3.1 高可用设计
- **LLM 故障转移**：主端点失败自动切换备用端点（阿里云 → DeepSeek）
- **多级缓存**：翻译记忆（LRU + SQLite）、知识库向量缓存
- **异步任务**：后台任务处理耗时操作，不阻塞主线程

### 3.2 可扩展性
- **模块化设计**：API 层 → 服务层 → 核心层，职责清晰
- **LLM 抽象**：统一接口，支持任意 OpenAI 兼容模型
- **向量库抽象**：内存/ChromaDB 可切换，适配不同场景

### 3.3 数据安全
- **JWT 认证**：支持角色权限控制（admin/operator/viewer）
- **API 用量追踪**：记录每次 LLM 调用的 Token 消耗
- **环境变量管理**：敏感配置不入代码库

### 3.4 性能优化
- **混合检索**：向量 + BM25，兼顾语义和关键词
- **翻译记忆**：高频翻译零延迟
- **结构化 Prompt**：减少 LLM 幻觉，提高输出质量

## 五、面试常见问题

### Q1：为什么选择 RAG 而不是纯 LLM？
**A**：纯 LLM 存在幻觉问题，回答不可控。RAG 通过检索知识库，保证回答有据可查，同时可以注入领域知识，提高专业性。

### Q2：混合检索怎么做的？
**A**：向量检索（40%）捕捉语义相似度，BM25（60%）捕捉关键词匹配，加权排序后取 Top-K。兼顾语义理解和精确匹配。

### Q3：翻译记忆怎么设计的？
**A**：两级缓存：进程内 LRU（10000 条）+ SQLite 持久化。命中缓存直接返回，未命中调用 LLM 后存入缓存。支持跨会话复用。

### Q4：亚马逊 SP-API 对接的难点？
**A**：
1. AWS Signature V4 签名复杂，需要精确计算请求哈希
2. 多站点配置管理，每个站点有独立的 endpoint 和 marketplace ID
3. OAuth 授权流程长，需要处理 Token 刷新和过期
4. 限流策略，需要实现重试和降级

### Q5：AI 与订单数据怎么联动的？
**A**：
1. 订单智能分析：拉取订单数据 → 统计销售趋势 → LLM 生成分析报告
2. 热销商品文案：从订单提取热销 ASIN → 查询商品详情 → 生成多语言文案
3. 客服订单上下文：查询订单详情 → 注入对话上下文 → 客服可回答订单相关问题

### Q6：如何保证 LLM 服务高可用？
**A**：设计故障转移机制，主端点（阿里云百炼）失败时自动切换备用端点（DeepSeek）。通过环境变量配置，无需改代码。
