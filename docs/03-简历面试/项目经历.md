## 国际贸易一站式智能服务平台（v0.2）　　　AI大模型应用开发工程师　　　2026/08 - 至今

### 项目背景：

针对外贸企业多语言沟通成本高、营销文案制作依赖资深业务员、客户咨询无法 7×24 响应、企业知识随人员流动流失等问题，设计并开发基于 DeepSeek / 小米 MiMo 双厂商大模型 + RAG + Agent 的一站式跨境电商智能运营平台。系统通过 RAG 检索增强生成实现可溯源的企业知识问答客服，通过持久化术语库与两级翻译记忆保证 30+ 语种译法一致性，覆盖智能客服、多语言翻译、智能文案、知识库管理、数据洞察、管理后台六大模块，帮助外贸企业「单人驾驭多语言交流」。

### 主要职责：

- 设计并实现四层分层架构（交互层 / 编排层 / RAG 检索层 / 数据与模型层），基于 FastAPI 完成六大模块 REST API；设计 LLM / Embedding / 向量库 / Agent **四大可插拔抽象层**，无 API Key 自动降级 Mock 保证全流程可跑；一套协议实现兼容所有 OpenAI 兼容厂商，配置三行即完成 DeepSeek、小米 MiMo 切换，亦可经硅基流动在 Qwen / GLM / Kimi 间一个 Key 随心切换。

- 实现 **LLM 多端点故障转移**：配置化备用端点链（`base_url|key|model`），主端点连接失败 / 超时 / 限流 / 鉴权失效时自动秒级切换，流式接口在首片段前同样生效；实测小米 MiMo 主端点 + DeepSeek 备用端点的完整链路，单点故障不再中断服务。

- 构建外贸领域 RAG 知识库，实现 PDF / DOCX / TXT / CSV / Markdown 解析、文本清洗（含 PII 脱敏）、语义分块、向量化入库；结合向量检索 + **BM25 关键词检索 + RRF 融合排序 + 可插拔重排序**构建 Hybrid Retrieval 混合检索体系，回答附知识来源、相关度与片段引用。

- **自建 52 条检索质量评测集驱动调优**：用评测数据定位未命中案例，实验发现权重配置问题并调整向量/BM25 融合比例，**Recall@3 从 96.2% 提升至 100%、MRR 达 0.981**；评测脚本可一键复跑，检索优化从「凭感觉」变为「看数据」。

- 主导检索性能优化：BM25 索引按语料指纹缓存（文档增删自动失效重建）、向量归一化矩阵惰性缓存，消除每次查询的全量重建开销，检索耗时压至毫秒级；文档按 doc_id 精确增删、租户内同名替换。

- 开发智能客服 Agent：规则意图识别（订单 / 售后 / 产品 / 翻译）、高风险问题自动转人工、多轮上下文管理；实现 **SSE 流式输出**（自研 LLM 流式解析 + 独立会话落库 + 前端 ReadableStream 分帧渲染），长回答首字秒出。

- 开发多语言翻译引擎：持久化术语库（FOB / CIF / L / C 等外贸术语）注入 Prompt 强约束专业译法；实现「**进程内 LRU + SQLite 持久化**」两级翻译记忆，跨重启命中（已实测），重复文本零模型调用成本。

- 开发智能文案模块：标题 / 详情 / 投放广告语 / 活动文案 / SEO 标签一键生成，**asyncio 多段并发**将延迟从四段串行之和降为最慢一段；前端提供文案模板卡片与示例商品一键填充。

- 落地**多租户隔离**：`tenant_id` 贯穿知识库、会话、看板全链路（Alembic 迁移演进表结构），检索层过滤候选阻断跨租户知识泄漏，配套服务层隔离测试。

- 建立安全与工程化体系：PBKDF2 + HS256 JWT 零依赖认证，修复注册自助提权漏洞并新增管理员授权接口，CORS 白名单自适应；**23 项自动化测试**（单元 / 冒烟 / 租户隔离）、Alembic 数据库迁移、Docker 生产编排（多 worker / 健康检查 / 环境隔离）、跨平台一键启动器。

### 项目难点：

- **单一大模型服务多场景，可用性与延迟双重压力**：文案"一键生成"需 4 次 LLM 调用（串行延迟叠加），且单一厂商故障即全局不可用。通过 asyncio.gather 并发（延迟降为最慢一段）+ SSE 流式（首字秒出）+ 多端点故障转移（主端点异常自动切换）组合解决，形成「快、稳」双保障。

- **检索质量无法量化，调优如同盲人摸象**：混合检索权重、分块大小等参数没有评测集支撑只能凭感觉。自建 52 条评测集（覆盖同义改写与英文关键词），以 Recall@K / MRR 为基线做受控实验，定位出「Mock Embedding 下向量路是噪声源」并完成权重调优——检索优化形成可复现的数据闭环。

- **外贸术语多语言译法不一致 + 关键词检索漏召回**：同一术语译法不统一直接影响合同沟通，纯语义检索又容易漏掉「L/C」等精确缩写。通过数据库术语库注入 Prompt 强约束译法 + 向量/BM25 双路召回 RRF 融合解决，答案附带来源可溯源。

- **多租户数据隔离**：共享一个向量库与对话库时，A 租户的知识可能泄漏进 B 租户的回答。通过检索候选租户过滤 + 数据表 tenant_id 全链路贯穿 + 隔离测试三道防线解决。

- **大模型幻觉与高风险对话风险**：商业客服不能给无依据回答，投诉退款法律类问题不宜由 AI 处理。通过「回答必须基于检索片段 + 附来源引用 + 知识库无相关信息时如实说明并转人工 + 高风险关键词规则兜底」四层机制解决。
