> 每条要点均对应真实代码（证据见第三节）。红线：不写 vLLM / LoRA / Supervisor / Redis / Kafka，不写任何杜撰指标；未落地的平台对接不写。

## 一、简历直接可用版

**跨境电商一站式智能服务平台**（个人独立开发）　2026.XX – 至今

技术栈：FastAPI · SQLAlchemy · Vue 3 · Element Plus · RAG · LangGraph · DeepSeek API

项目简介：面向外贸企业的多语言智能服务平台，覆盖商品文案生成、多语言翻译、RAG 智能客服、知识库管理、数据洞察与后台管理六大模块；LLM / Embedding / 向量库全链路可插拔，无 Key 时降级 Mock，开箱即可跑通全流程。

- 设计可插拔模型抽象层：LLM / Embedding / 向量库均接口隔离（mock / openai_compatible / chroma 多实现），换供应商只改配置不改代码
- 实现 RAG 客服链路：BM25 + 向量双路召回、RRF 融合、重排序、多轮上下文与知识溯源，并编写离线评测脚本支撑检索质量回归
- 构建知识库流程：多格式上传、清洗、分块、向量化与增量导入，配套示例库支持端到端演示
- 开发多语言翻译引擎并落地持久化术语库，保证跨语种译法一致，随知识库增量更新
- 自实现鉴权：标准库完成 PBKDF2 密码哈希与 HS256 JWT 签发校验，零第三方安全依赖，演示/生产双模式切换
- 编排 Agent 服务：规则路由工作流，安装 LangGraph 后升级为 StateGraph 图编排，按意图分发文案/翻译/客服子流程
- 打造一键启动器：依赖哈希缓存（未变更跳过安装）、按端口反查 PID 一键停止、状态自检，双端秒级冷启动
- FastAPI 分层架构（api / services / core / db）+ Vue 3 六大功能页面，Docker Compose 本地编排

> 投递按 JD 取 5~6 条：RAG 岗优先 2/3/4/6，工程岗优先 1/5/7/8。

## 四、追问预判

**Q1 混合检索为什么这么做？** BM25 保 SKU、型号等术语的精确匹配，向量管同义改写；两路 RRF 融合后重排序（配置默认权重：向量 0.4 / BM25 0.6）。评测脚本可现场演示——实测 Recall@3=100%、MRR=0.942，但要主动说明"52 条小集合，价值在回归流程"；**简历文本不写具体数字**。

**Q2 向量库为什么先用内存？** 脚手架以可运行为先，接口已隔离，切 Chroma 只改配置——是可插拔设计，不是没做完。

**Q3 JWT 为何不用 pyjwt？** 依赖最小化，标准库手写吃透签名校验细节（过期、alg 不可信、时钟偏移）；生产会换成熟库。

**Q4 LangGraph 怎么讲？** 措辞是"可选依赖，安装后升级"。被追问就讲图节点按意图分发，**不要说成 Supervisor 多智能体**。

**Q5 接真实电商平台了吗？** 诚实说未落地，讲清设计思路（ChannelAdapter 抽象、OAuth、限流退避、PII 脱敏），再把话题拉回 RAG 主线。

**Q6 启动器算亮点吗？** 当工程素养一句带过，不当主亮点。
